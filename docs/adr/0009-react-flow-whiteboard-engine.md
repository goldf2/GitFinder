# 使用 React Flow 替换自研白板引擎

日期：2026-09-01

状态：已接受，分阶段实施

## 背景

关系白板的一方生产代码已经达到 14,545 行，其中控制器约 7,452 行、关系样式约 3,627 行。大量代码在重复实现通用画布能力：平移与缩放、框选、拖动、边缘自动滚动、嵌套容器、尺寸调整、连线、节点工具条和小地图。继续拆文件只能改变单文件大小，不能把整体代码缩减到目标规模。

## 决策

采用 `@xyflow/react` 12 作为关系白板的画布引擎，并把它作为现有原生页面中的独立 React 区域接入；应用导航、资源库、检查器、Electron 主进程和其它页面不迁移到 React。

React Flow 负责：

- 节点、容器和连线的渲染生命周期；
- 选择、框选、拖动、边缘自动平移；
- 滚轮或触控板双指滚动围绕指针缩放、双指捏合缩放，中键或空格加拖动平移；
- Project 父子节点约束、节点尺寸调整、节点工具条；
- 视口、适合内容、控件和小地图。

GitFinder 继续负责：

- `服务器 → Project → 部署 → 访问点` 的领域结构；
- Coolify 事实读取、仓库关联、检测状态与归档；
- 白板文件格式、迁移、资源和原生文件操作；
- 结构命令、布局选择、显示选项及业务规则；
- 卡片视觉内容和用户可见文案。

首个切片复用现有无状态布局结果，不同时引入第二个布局依赖。只有当 React Flow 已替代正式渲染和交互、现有布局代码仍然是主要体积来源时，才单独评估 ELK。

## 代码量目标与口径

基线为以下关系白板一方生产文件合计 14,545 行：`src/renderer` 的关系控制器和样式、`src/shared` 的关系模型/投影/布局、`src/main` 的白板服务与 IPC。

目标为同一口径不超过 4,848 行。统计不包含 `node_modules`、测试、文档、视觉夹具和构建生成物。依赖库代码不计入一方代码，但依赖数量和打包体积必须在发布验证中记录。`npm run measure:whiteboard` 使用固定文件清单报告当前值；迁移完成后把它升级为发布失败门禁。

迁移期间允许一个有明确删除期限的兼容入口；不允许把新旧两套完整渲染器长期保留。每完成一个垂直切片，就删除被库取代的旧实现和对应 CSS，而不是只增加适配层。

## 兼容约束

- 现有 `board.json` / `.gfb` 数据与资源目录保持兼容。
- `groupId` 仍表示结构归属，布局不能修改它。
- 结构、布局、容器形状和状态视觉保持独立。
- 旧白板中的坐标、尺寸、视口、归档、别名、备注和仓库关联必须可读取。
- React Flow 内部节点/边格式只存在于渲染适配层，不写入持久化文件。
- 原生保存、打开、重开与安装版验收仍是发布门禁，浏览器夹具不能替代。

## 迁移顺序

1. 建立纯函数适配器，把现有实体、放置和关系转换为 React Flow 节点与边。
2. 在隔离夹具验证卡片、Project 容器、曲线、框选、平移/缩放、小地图和尺寸调整。
3. 用新渲染器替换正式白板的图层与指针事件，保留现有命令和持久化入口。
4. 迁移工具条、检查器和资源拖入，并删除旧 DOM 渲染、走线、手势与小地图代码。
5. 达到功能对等后删除兼容入口，执行代码量门禁、全量测试、安装版验收。
