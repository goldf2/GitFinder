# 关系白板模块边界

日期：2026-09-01

状态：由 ADR-0009 部分取代。领域模型、结构/布局分离和文件兼容约束继续有效；“不引入构建工具或新运行时依赖”不再适用。

## 背景

关系白板已同时包含 Coolify 数据投影、Project 归属、七种空间布局、卡片与群组渲染、鼠标/触控交互、检查器、资源库和白板文件持久化。继续把这些职责放入单个控制器或单个投影文件，会让“结构开关”“布局方式”和“显示效果”互相覆盖。

## 决策

保留现有 `RelationshipBoardController` 和 `PanelTopologyProjection` 作为兼容入口，但实现按以下方向拆分：

1. **领域模型**：`relationshipGraphModel.js` 只负责白板数据格式、默认值、迁移和校验。
2. **结构投影**：Project/访问点归属属于结构规则，不写坐标；独占访问点可属于 Project，共享访问点保持外部唯一节点。
3. **布局基础**：区域打包、排序和几何算法是无状态纯函数。
4. **布局引擎**：树状、紧凑、泳道和 Project 星系只读取结构并写坐标/容器尺寸，不修改来源事实和成员归属。
5. **显示模板**：结构菜单、布局菜单和显示设置只描述命令与状态，不执行数据投影。
6. **控制器**：负责命令编排、历史记录、持久化与渲染调度；不再内嵌具体布局算法或大段菜单定义。
7. **交互与文档服务**：指针/键盘手势、检查器、资源库和白板文件操作继续按可验证切片迁移，迁移期间由兼容入口保持调用方式不变。

模块同时支持浏览器全局脚本和 Node `require`，不引入构建工具或新运行时依赖。

## 不变量

- `groupId` 只能由结构命令或明确的用户分组操作改变，布局函数不得修改。
- `view.structure`、`view.layout`、显示设置和卡片/容器外观彼此独立。
- “项目组包含访问点”开启时，独占访问点既属于 Project，也显示在容器内部；关闭时位于容器外部；共享访问点始终独立。
- 白板文件、动态布局覆盖、撤销/重做和旧字段迁移保持兼容。
- 每次迁移先增加或保留行为测试，再替换实现；公开入口在迁移完成前不删除。

## 第一阶段

先拆出布局基础、Project 结构规则、Project 星系布局和结构/布局菜单模板。这些边界覆盖当前最频繁变化的代码，并可直接验证结构、布局和显示不再互相覆盖。后续再迁移卡片渲染、检查器、指针交互和文档操作。
