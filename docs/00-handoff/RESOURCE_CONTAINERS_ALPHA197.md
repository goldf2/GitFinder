## 根因及相邻入口审查

| 入口/环节 | 原行为/缺口 | 本轮处理 |
| --- | --- | --- |
| 新本机白板、独立白板 | 非server-tree结构仍显示旧主机图标 | 使用同一个HostBubble显示主机，不强制修改整张白板的structure/layout |
| 资源库主机加号 | 只添加一条entity/placement，缺少下级和关系 | 选择该主机的Project、部署、端点及真实关系，一次原子操作加入 |
| 云Project | 临时资源别名被当成普通本地项目卡片 | 对应真实物理Project容器；同Project在不同主机分开，主机下入口只选该主机范围 |
| 不同Coolify来源复用Project UUID | 仅按UUID去重、查找，可能串来源或漏资源 | 加入provider身份，不按显示名称猜测；本地项目ID与云Project UUID分开 |
| 部署、端点 | 单独添加部署不保存端点/边关系 | 部署带访问点及真实关系；单独端点不反向导入其它部署 |
| 实时资源拖拽 | transient判断禁止主机、部署、端点拖动 | 加号与拖放共用同一个组合入口；已添加主机/Project/部署可显式“补全” |
| 重复添加/旧主机快照 | 只有定位，没有补全路径 | 幂等补缺；保留现有ID、坐标、锁定、备注和手动分组，不自动重写用户白板 |
| 离线保存/跨白板使用 | runtime被正确剥离后，部分代码不再识别Project；新空白板又查不到其它已保存白板的组归属 | 复用稳定Project生成ID识别，查询已保存来源的placement；不将runtime写入便携数据 |
| 主机容器动作与位置 | 空容器按fallback重建导致回弹，普通placement转换找不到synthetic host；连续读回可能累加位移 | 空容器保留拖动，按初始显示/原始位置换算一次；真实主机关系端点映射到显示容器，锁定生效 |
| 主机/Project标题与定位 | 新混合白板可能使用另一套标题或定位旧隐形卡片 | 共用嵌套标题和标题空间；定位主机适配真实渲染边界 |
| 画布隐藏运行层 | 资源库也随之失去来源，无法重新添加 | 资源库读取已有来源，不依赖画布层可见性；显式添加恢复运行层且可一并撤销 |
| 本地项目/Git仓库、普通分组、媒体 | 本地引用/手工元素有不同语义 | 保留原引用卡片与媒体生命周期，不擅自展开本地目录、重建Git仓库或复制整张白板 |

## 实现约束

`relationshipResourceComposition.js`只选择来源实体、placement和真实关系。控制器复用已有`panelTopologyProjection`生成按主机分开的Project，再仅排列选定的新来源分支；不会把其它主机的整个投影带入当前白板。组合候选先经现有模型完整验证，再写入历史/内存，容量或格式失败不留下半个容器。共享端点按实体ID复用，实际多部署复用的告警仍保留。

旧容器/卡片的备注、锁定、坐标和手工归属优先。补全不等于远端全量覆盖，不主动删除旧快照，也不取消用户单独隐藏的下级。离线快照的事实与实时状态分开；未进行数据格式迁移。画布上主机外框是可重新计算的显示对象，不把`host-bubble:`写进领域关系或持久化成员。

项目内任务记录继续使用唯一`management/development-tasks.json`。仪表盘/开发进度的测试功能开关保持默认关闭，不恢复正式开放。

## 开发中失败的区分

首次UI脚本把创建对话框的Promise作为CDP同步返回，等待用户输入时超时；改为保留Promise后再驱动表单，实际创建流程通过。

空主机持续读回重复累计偏移是本轮发现并修正的代码问题。另一个UI严格位移断言最初直接用12px首步跨越拖动阈值，XYFlow在激活拖动时才记录指针起点，导致结果比按mousedown计算少首步；对已安装依赖源码核对后，测试先发1/2/3px小步激活再测量。未将该测试驱动问题误计为产品精度修复，也未保留无证据的拖动起点算法改写。
