# GitFinder 2 设计与实现决策

## GF-ARCH-20260905-01 · 白板作为真实系统拓扑与代码架构入口

- 状态：方向确认，待分阶段实现
- 确认时间：2026-09-05。
- 决策：内置关系白板不再定位为 Excalidraw 的通用绘图替代品，而定位为 GitFinder 的事实驱动可视化入口。它直接展示本地项目/仓库、Coolify 部署、主机、访问点及其关系；白板中的手工布局和注释属于呈现层，不改写资源事实。
- `goldf2/archify` 作为代码结构分析层接入：仓库分析生成可验证的架构、工作流、时序、数据流或生命周期快照，并从仓库节点进入代码架构视图。运行拓扑和代码架构必须分层显示，合并视图只通过明确的仓库/项目关联连接，不能把推断的代码关系冒充为运行时关系。
- 第一阶段优先采用“只读分析 + 快照缓存 + 白板入口”方式，不把 Archify 渲染器直接耦合进关系图核心；保留提交号、生成时间、来源和验证状态，离线时继续显示最后一次有效快照。
- 后续阶段再实现代码组件与运行资源的跨层关联、提交前后架构差异和源码证据跳转。所有自动刷新都必须标注事实来源和新鲜度，分析失败不能覆盖最后一次有效结果。
- 视觉参考：吸收 Archify 的清晰 SVG 图形、语义类型色、搜索/聚焦、上游/下游追踪、路径探查、主题切换和完整图卡导出等交互；不照搬其自包含 HTML 运行时，也不把 GitFinder 白板改成不可编辑的展示页。GitFinder 继续以本地资源事实、可拖动容器、关系警报和离线持久化为优先。

## D-UI-001 · 使用最终级联层建立共享 Apple 界面基础

- 状态：采用
- 日期：2026-09-05
- 背景：现有界面按功能拆分为多份大型 CSS，应用外壳、设置、菜单和白板工具条重复定义相似的材质与交互状态；当前工作树又有多个并行任务，直接重写或格式化旧文件风险较高。
- 决策：新增 4 行 `src/renderer/styles/apple-ui.css` 作为唯一入口，在 `theme.css` 后按顺序导入 `tokens.css`、`app-shell.css` 和 `settings-board.css`。语义 token 和分组选择器统一系统字体、圆角、材质、阴影、焦点、按压、禁用与辅助功能回退；功能 CSS 继续拥有业务布局。
- 结果：10 类常用控件复用一组反馈规则，外壳、设置与 10 类菜单/浮动工具条复用同一材质层级。初版 711 行覆盖层收缩为 496 行模块源码，同时从四份旧功能 CSS 删除 202 行重复视觉声明；计入删减后 CSS 净新增 295 行。

## D-UI-002 · 系统主题和辅助功能偏好属于基础能力

- 状态：采用
- 日期：2026-09-05
- 决策：共享层必须同时定义深色 token，并为 `prefers-reduced-motion`、`prefers-reduced-transparency` 和 `prefers-contrast` 提供明确回退。按压反馈应即时且克制，减少动态时取消缩放反馈。
- 结果：默认主题保持现有配置机制；基础层只读取已有 `data-effective-mode` 和系统媒体查询，不新增设置存储或业务状态。

## GF-DRAG-20260905-03 · Project 容器跟随上级

- 确认时间：2026-09-05 07:40:34 +0800。
- 用户明确要求：Project 容器应该可以跟随上级一起被拖动。该要求替代 alpha.92 的“主机联动时 Project 本身保持原位”行为。
- 实现语义：上级开启“固定下级”后，实际部署关系所关联的 Project、全部物理成员和满足条件的外部访问点同位移；容器尺寸及成员相对位置保持。关闭开关后不联动。
- 共享/手工容器：任一关联主机启用固定下级均带走整个容器，不反向移动另一主机；仍有静止部署的外部共享访问点不移动。
- 不改写 groupId 或服务端来源事实；仅派生主机到容器的移动依赖。已归档部署不新增可见容器的上级依赖。
- 验收：alpha.94 专用回归 15/15、全量 991/991 通过；安装版实际鼠标拖动与普通重开持久化均通过，已安装并推送。详见 CURRENT_STATE.md 和 GF-DRAG-20260905-03。
