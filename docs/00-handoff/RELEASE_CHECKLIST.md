# GitFinder 发布验收清单（仓库内权威入口）

> 2026-09-16 从本机被Git排除的 `CODEX_RELEASE_VALIDATION.md` 迁入本目录，以便干净克隆可独立接续；原流程范围不变。历史清单建立于 2026-09-04。适用于版本升级、打包或用户可见桌面功能变更；源代码或 CI 通过不能单独证明发布完成。

## 先确认

1. 明确当前 checkout、目标版本、变更功能、目标 OS 与产物名称。
2. 先检查发布脚本/CI、测试命令、语法或 lint、打包配置与工作树状态。
3. 找到真实产物和目标环境。macOS 可使用 `/Applications/GitFinder.app` 或当前项目的 packaged app；Windows 必须有当前 VM 产物和正常启动路径。

## 流程

1. 运行当前自动化源码门槛，并记录准确通过数量/输出。
2. 针对每个目标平台单独打包，验证预期安装包、元数据/校验和与失败输出；源码兼容不等于 NSIS/ZIP 可打包。
3. macOS 替换前可恢复地保留旧应用，安装新包，确认可启动、可见版本和浏览位置。
4. Windows 在 VM 中经普通用户路径安装/双击默认启动；不得只用 `--disable-gpu` 启动。启动后完成一个基础交互。
5. 做功能专项真实应用验收：
   - 标签：分配、筛选、列表/图标/列/图库检查，并确认本地设置边界；
   - 关系白板：确认事实/关系，`定位` 只影响本地投影；组/卡变更先在隔离白板验证选择、编辑、保存、重开和连线路由，再改真实布局；
   - 标签页溢出：双向翻页、选择恢复页签、验证面包屑/内容对齐；
   - 终端入口：目录、文件夹、普通文件分别测试；确认能打开终端但不执行命令或扩大受控路径。
6. 分别报告源码、打包、安装、默认启动和交互门槛；未完成或仅观察到的项目明确标为未验证。

## 常见误判

- Windows CI 以 `--disable-gpu` 启动但普通启动崩溃：这是覆盖缺口，修复后必须在 VM 验证默认/GPU 路径。
- 源码测试通过但 NSIS/ZIP 失败：打包单独失败，不能称为可发布。
- 仅观察到一个终端目标或 fixture 成功：只算部分观察，仍要完成真实应用矩阵。

## 完成清单

- [ ] 已确认当前版本、checkout、产物和目标 OS。
- [ ] 自动化源码检查通过且记录了准确结果。
- [ ] 所有目标平台完成打包。
- [ ] 目标已安装应用/VM 通过正常用户路径启动。
- [ ] 变更的可见工作流通过专项检查。
- [ ] 报告清楚区分已验证、失败和未验证。
