# GF-WORKSPACE-221 · 项目形态与精简仓库工作区

## 范围与基线

2026-10-01，基于1097d3c / 2.0.0-alpha.220的独立工作树实施。用户先要求给项目设置App/Web类型，随后要求简化仓库工作区显示。原主目录已有未提交内容保持原样；本轮不执行项目发布、商城写入、服务器部署或真实仓库的Git写操作。

## 实现

- 项目设置新增“项目形态”：未分类、App项目、Web项目、App + Web。可在仓库页名称旁的紧凑标签进入设置，项目卡片也显示已配置类型。
- `projectKind`作为schemaVersion 1项目清单的可选字段保存在`.gitfinder/project.json`；缺失时读取为unclassified，不扫描推断、不在读取时重写旧文件。旧调用省略字段保持已有值，非法值拒绝。分组成员保持独立，不新增重复分组层级。
- 仓库概览使用已有顶部标题，不重复渲染仓库名称及同路径项目按钮；真实父级关系与独立仓库状态保留。
- 隐藏零值计数；远端领先/落后计数明确为本地缓存。Fetch、Pull、Push、分支与远程及刷新收进“更多”，只常驻审查与提交；原完整Git操作及权限逻辑不改。
- 文件列表使用分隔线代替逐项卡框；默认8条，更多文件可展开，差异区可关闭。
- 最近提交默认显示5条，其余本次读取的记录可展开；不声称这就是仓库全部历史。作者保留在完整提示中，避免每行重复占位。
- 移除Git概览中只有刷新按钮的独立工具栏，文件浏览和项目浏览原工具栏不受影响。

## 验证入口与边界

`npm run check`执行当前仓库测试、renderer构建与JS语法检查。
`node scripts/verify-unified-workspace.js`执行实际Electron、独立profile和临时项目的交互回归；加入类型切换/保存/取消/退出重启、分组及Git文件不变、菜单/差异/提交展开、900/1100/1440px布局检查。Fetch/Pull/Push只验证UI调用路由，使用明确的测试替身，不执行网络Git写入。
安装版复验同一脚本，加`--app <安装App的Contents/MacOS可执行文件>`；不复制真实config、令牌或用户项目进测试profile。
