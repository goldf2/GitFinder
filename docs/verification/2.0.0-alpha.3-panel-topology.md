# GitFinder 2.0.0-alpha.3 Panel 动态白板验证记录

- 验证日期：2026-08-29
- 验证平台：macOS arm64
- 验证对象：`/Applications/GitFinder 2 Alpha.app`
- 结论：客户端首批垂直切片和隔离 Mock 可见闭环通过；真实 Panel、Windows 与普通 macOS 更新启动未通过验收

## 已实现

1. Panel Provider 使用只读 `topology:read` 能力读取 `/api/gitfinder/v1/topology`，严格限制响应大小、节点数量、标识、URL、时间和延迟范围。
2. `.gitfinder/deployments.json` 升级为 schema v2，可为一个部署记录多个 `repositoryIds` 和一个 `primaryRepositoryId`，继续兼容读取 v1。
3. 纯投影模型用确定性 ID 生成“服务器 → 部署 → 仓库 → 项目”关系；动态实体、关系和布局只在渲染时合并。
4. 关系白板显示 Panel 连接状态、服务器/部署计数、最近失败计数，并支持手动刷新和 30 秒轮询。
5. 动态节点显示当前状态、延迟、更新时间、最近部署失败、分支、部署提交和本地仓库关联；检查器只读。
6. 本地项目扫描和逐项目关联读取在后台执行，不阻塞关系白板首屏。

实际安装应用中确认：

1. 版本显示为 `2.0.0-alpha.3`。
2. 白板首屏不等待全盘项目扫描，能够显示 `Panel 1 台服务器 · 2 个部署 · 1 个最近失败`。
3. 服务器 `Con01` 显示 `online`、`28 ms` 和更新时间。
4. 部署 `GitFinder 2 Demo` 显示 `running`、`42 ms` 和“最近部署失败：否”。
5. 部署 `GitFinder Worker` 显示 `degraded`、延迟未知和“最近部署失败：是”。
6. 失败部署检查器显示环境、服务器、失败时间、`Mock health check failed`、分支 `main` 和提交 `89abcdef01234567`。
7. 手动刷新后仍有 3 个动态节点和 2 条派生关系。
8. 刷新前后 `relationship-boards.json` 的 SHA-256 均为 `d77048e467559042b228902baa7e4b517009e25569fb69ebbdd34bbf377e82dd`，证明动态事实未写入持久白板。

## 尚未验证与阻塞

### 真实 Xiangshu Panel

仓库中没有生产 Panel 服务源码，真实服务也尚未提供本切片要求的 `/api/gitfinder/v1/topology` 契约。因此当前只验证了客户端与 Mock，不代表真实 Panel 已接通。

### 普通 macOS 更新启动

不带测试参数启动时，主进程在创建窗口前阻塞于 `SecItemCopyMatching`。系统中没有可用 Developer ID 身份，alpha.2 与 alpha.3 都是 ad-hoc 签名且代码身份变化，旧 `GitFinder 2 Alpha Safe Storage` 钥匙串项不会自动授权新构建访问。

需要以下任一条件后再做普通双击启动验收：

1. 用户在 macOS 钥匙串提示中授权新应用访问；或
2. 后续构建使用稳定的 Developer ID 签名。

本次没有删除或重置钥匙串项，也没有把 `--use-mock-keychain` 作为产品配置，因此不能把隔离 Mock 运行描述为普通安装启动通过。

### Windows

本版本未在真实 `windows-latest` runner 或用户 Windows 虚拟机中构建、安装和交互验证；不得描述为已有可发布 Windows 版本。
