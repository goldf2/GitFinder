# GitFinder 2.0.0-alpha.7 可编辑关系与自动发现边界

## 本次目标

1. 节点卡片不再只有标题区域可拖动，除连接点和交互控件外，整个卡面都可以开始拖动。
2. 本机关系事实支持编辑关系类型和显示名称。
3. 关系方向可以反转，并自动换成语义相反的预设。
4. Panel 动态关系继续保持只读，不把远端观测伪装成人工事实。

## 关系预设

- 项目与部署：包含/属于、部署来源/从仓库部署、运行于/托管运行、对外提供/由部署提供。
- 依赖：依赖/被依赖。
- Git 仓库：Fork 来源于/作为 Fork 源、镜像、作为子模块/包含子模块。
- 通用：连接到、关联。

检查器只列出当前起点和终点类型允许使用的预设。关系还可以填写最多 80 个字符的自定义显示名称，但底层类型仍保留为受控值，避免任意文本破坏关系推理。

反转不是只改变箭头：例如“项目包含仓库”会变为“仓库属于项目”，“部署运行于服务器”会变为“服务器托管运行”，“仓库 A Fork 来源于仓库 B”会变为“仓库 B 作为仓库 A 的 Fork 源”。修改与反转都进入同一撤销、持久化和模型校验流程。

## 哪些关系可以自动识别

### 本地 Git 可直接取得或高可信推导

- `.gitmodules`：父仓库与子模块仓库。
- `git remote get-url --all`：本地仓库与远端地址。
- `git rev-parse @{upstream}` / `git for-each-ref`：本地分支与跟踪分支。
- `git worktree list --porcelain`：同一仓库的工作树。
- `git merge-base`、提交对象和 remote 引用：共同历史、领先/落后和可能同源。
- GitFinder 目录扫描：项目包含的仓库、嵌套仓库和独立子项目边界。

### 需要托管平台或外部系统确认

- Fork 父仓库/源仓库：仅共享提交历史不能证明平台 Fork；需要 GitHub、GitLab、Gitea 等 API 的 `parent/source` 元数据。
- 平台镜像、归档、模板仓库和仓库所有权：需要托管平台元数据。
- 仓库到部署、部署到服务器、部署到域名：由 Xiangshu Panel 聚合 API 提供只读事实。

后续自动发现应先生成“关系建议”，显示证据来源、检测时间和可信度，由用户确认后再写入本机白板；不得覆盖人工关系，也不得把共同历史直接标记为已确认 Fork。
