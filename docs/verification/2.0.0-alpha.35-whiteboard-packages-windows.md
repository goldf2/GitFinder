# alpha.35 白板包与 Windows 测试版

## 本次范围

白板文件夹保持默认工作格式；新增 `.gfb`（标准 ZIP）导入导出。导入创建新项目文件夹并加入资源库；复制的媒体随包携带，外部引用默认询问收集，未找到/未授权资源保留占位。应用会话与本地授权记录不打包。

入口：白板工具栏“添加节点（＋）” → “导出白板包…” / “导入白板包…”；“打开…”也能选择白板包。旧 JSON 快照菜单继续保留并明确与附件包区分。

## 已验证

- macOS：816 项测试通过，201 个 JavaScript 文件语法检查通过。
- Windows 11 ARM64 虚拟机、x64 Node 24.12.0：816 项测试，797 通过、19 项平台相关跳过、0 失败。
- Windows 普通用户的 Electron x64 运行时：便携项目配置、目录读取、Git、复制、移动、回收站、白板包附件往返、导入后保存通过。
- 标准 `unzip -t` 可读取测试 `.gfb`，`board.json` 和 PNG 附件校验通过。
- 正式白板组件的浏览器检查：包导入导出与 JSON 菜单可见。此项不替代原生文件对话框验证。
- Windows 原生应用：可见 `v2.0.0-alpha.35` 主窗口；免安装程序和 NSIS 安装后程序均无额外启动参数运行超过 8 秒，未退出。隔离目录安装、启动、卸载全部通过。
- 已生成 x64 NSIS 安装包和免安装 ZIP，复制到本机后 SHA256 与 Windows 构建结果一致。构建未进行远程发布。

## 构建与环境说明

- 源码版本 `2.0.0-alpha.35`。本次不提交或推送仓库，不更新本机 macOS 安装。
- Windows 依赖初次下载遇到网络等待；切换下载来源并校验 Electron npm 包内的官方 SHA256 后继续。构建脚本允许 `GITFINDER_ELECTRON_ZIP` 指定同版本的已校验 ZIP；校验不符时拒绝构建。
- Windows 普通用户测试初次有 16 项因创建符号链接 `EPERM` 失败；SYSTEM 默认临时目录又触发产品对 Windows 系统目录的保护。最终在具有符号链接权限的测试进程中，将 Node `os.tmpdir()` 指向本次独立构建目录的 `test-tmp` 后全量通过；未修改系统目录保护或 Windows 安全设置。
- 包验收脚本改为独立临时安装目录，避免覆盖已有安装。运行前已检查目标用户无同名安装、快捷方式和运行进程。

## 验收边界

- 安装包未签名（`NotSigned`），是内部测试版，Windows 可能提示未知发布者。
- 实测环境为 Windows 11 ARM64 虚拟机中的 x64 程序；尚未验证 Intel/AMD Windows 实机、Windows 10 或 ARM64 原生构建。
- 白板包通过 Windows 运行时真实文件往返、附件及保存测试；原生界面逐步点击导入、导出对话框并确认图片显示仍待验收。虚拟机被其他操作占用后停止 UI 接管，未把接口测试宣称为界面验收。
- 安装验收用的临时安装已卸载，免安装构建和测试资料保留。恢复了虚拟机原有的闲置暂停设置，没有更改 USB 设备归属。
- macOS 本机安装仍为原版本，本次只构建 Windows 测试版。
