- 验证对象：`/Applications/GitFinder 2 Alpha.app`
- 结论：多个 Panel 地址的独立会话、聚合拓扑和单地址移除通过；受管位置移除入口、原生确认和配置回退通过；真实 Panel 与 Windows 未验证

## 实现变化

1. Panel 会话升级为 schema v2，可保存最多 12 个地址；每个规范化根地址生成独立稳定的 `providerId`。
2. alpha.4 的单 `provider` 会话在首次读取时原子迁移为 `providers[]`，不读取系统钥匙串。
3. 设置页同时展示全部连接；同地址重新连接只更新该地址，移除只清除选中的应用会话，其他地址和项目非敏感关联保留。
4. 目录、项目详情和关系白板按 Provider 聚合 Panel 资源；跨 Panel 出现相同 `nodeId` 或 `resourceUuid` 时使用 Provider 复合身份隔离。
5. 项目可同时保存多个 Provider 的部署关联，绑定配置只记录 Provider 与远端资源 ID，不记录令牌或绝对本机路径。
6. 左侧“位置”根节点增加移除按钮。操作只删除 GitFinder 的受管位置记录，不删除磁盘上的目录或文件；当前目录因此失去访问范围时会回退到仍受管的位置。
7. 修复原生 `window.confirm` 失去 Window 接收者后点击移除无响应的问题，并加入回归测试。
