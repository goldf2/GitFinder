# GitFinder 2.0.0-alpha.4 应用会话与普通启动验证记录

- 验证日期：2026-08-29
- 验证平台：macOS arm64
- 验证对象：`/Applications/GitFinder 2 Alpha.app`
- 结论：不使用系统钥匙串的应用会话、普通安装启动和 Mock Panel 跨重启动态白板闭环通过；真实 Panel 与 Windows 未验证

## 实现变化

1. 主进程不再导入或调用 Electron `safeStorage`。
2. Cookie Encryption Fuse 关闭，Chromium 启动不再访问 `GitFinder 2 Alpha Safe Storage`。
3. GitFinder 不接收或保存 Panel 密码；只读访问令牌作为应用会话保存在用户数据目录的 `panel-session.json`。
4. POSIX 会话文件以 `0600` 原子写入，读取时发现组/其他用户权限会拒绝使用；公开连接状态不返回令牌。
5. 旧 `panel-provider.json` 的钥匙串密文不解密，只保留非敏感地址和名称用于“需要重新连接”提示。
6. 新会话跨进程重启恢复；断开连接删除会话，但不删除项目中的非敏感部署关联。

## 明确边界

- 会话令牌没有系统级加密；它依赖当前系统用户的数据目录权限。同账户恶意进程仍可能读取，因此只允许短期、最小权限、可撤销令牌。
- 真实 Xiangshu Panel 生产 `/api/gitfinder/v1/topology` 尚未实现或连接，本次数据来自本机 Mock。
- Windows 的用户目录 ACL、会话恢复、安装、启动和动态白板尚未在真实 Windows runner/虚拟机验证。
- SSE、故障/恢复通知、冷却、免打扰和写操作仍不在本次交付范围。
