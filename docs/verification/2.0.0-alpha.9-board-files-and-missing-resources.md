# GitFinder 2.0.0-alpha.9 白板文件与缺失资源保留

## 本次目标

关系白板既继续自动保存在 GitFinder 用户数据中，也可以把当前白板显式导出为一个可移植 JSON 快照。快照可以导回 GitFinder，并在外部项目、仓库或 Panel 节点暂时不可用时保留节点、布局和连线。

## 文件格式与边界

- 新文件使用 `gitfinder.relationship-board` 格式标识和独立的文件格式版本号。
- 每次只导出当前白板，包含当前白板上的持久节点、可见 Panel 只读投影节点、关系、视觉分组、布局、视口与筛选显示偏好。
- 导出前经过严格关系模型和敏感内容检查；疑似密码、令牌或私钥会被拒绝。
- 文件不保存本机绝对路径、Panel 登录状态、令牌、Cookie 或运行时对象。
- 导出采用临时文件写入和安全替换；导入继续采用“预览差异后确认合并”，确认前零写入，应用前再次校验文件指纹与本机白板版本并创建备份。
- 导入同时兼容此前直接保存关系 store 的旧版 JSON。新格式会保留 `observed` 等事实来源和关系自定义显示名称。

## 缺失资源语义

- 项目或仓库稳定身份当前无法在本机注册表解析时，节点显示“缺失”。
- 从导出快照恢复的 Panel 服务器、部署或端点当前未被 Panel 动态拓扑返回时，节点显示“缺失”。
- 缺失节点使用明确的琥珀色虚线提示，但不降低节点透明度；属性栏说明资源缺失原因。
- 缺失不等于删除：节点、关系、布局、事实字段、编辑能力和再次导出均保留。资源重新出现且稳定身份匹配时，界面自动恢复正常解析。
- 关系引用一个完全不存在的节点记录属于文件结构损坏，仍会在导入校验阶段拒绝；系统不会凭空猜测节点类型或身份。

当前关系模型尚未提供独立“文件节点”类型。后续只有在确定“项目稳定身份 + 项目内相对路径”的跨平台身份规则后，才会把文件加入相同的缺失与恢复机制；不会把绝对文件路径写入可移植白板。
