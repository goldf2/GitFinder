# 关系白板云同步边界

- 状态：已规划，尚未实现
- 原则：云端同步关系协作数据，不上传本机路径和登录凭据

## 为什么不把所有数据都保存到云端

Coolify 本身是服务器、项目、环境和部署状态的事实来源。GitFinder 不应复制一套部署数据库；白板云端只需保存跨设备共享的关系、布局和稳定引用。绝对路径、目录授权和 Token 与设备绑定，上传后既不可移植又扩大安全风险。

## 可同步

- 白板 ID、名称、说明和修订号。
- 稳定实体引用：`projectId`、`repositoryId`、`providerId`、`nodeId`、`resourceUuid`。
- 用户创建的节点、关系类型、方向、分组、坐标和折叠状态。
- 资源缺失标记所需的最后已知名称和类型。
- 手工核验时间、备注和关系来源，不包含动态响应原文。

## 仅保存在本机

- macOS 路径、Windows 盘符、UNC 路径和目录授权记录。
- Coolify 根地址、API Token、Cookie、密码、SSH 私钥和任何可恢复凭据。
- 窗口、标签页、最近目录和文件操作历史。
- 当前设备解析出的本地项目与仓库实际路径。

## 不重复存储

- Coolify 当前运行状态、部署历史、服务器设置和域名仍由 Coolify 实时读取。
- 云端白板只保存稳定引用和最后已知显示标签；离线时明确标记为缓存，不冒充实时状态。

## 后续最小切片

1. 服务器端提供经过身份验证的 board list/get/put API，并使用 revision 或 ETag 做乐观并发控制。
2. 首次同步前显示本地与云端差异；冲突时由用户选择合并、保留本地或保留云端。
3. 删除使用 tombstone，避免离线设备重新上传已删除关系。
4. Token 继续保存在每台设备自己的 `coolify-session.json`；新设备必须单独连接 Coolify。
5. 只有完成双设备冲突、离线恢复和敏感字段扫描后，才能把该能力标记为已实现。
